No endpoint accepts client prices or stock as a checkout source of truth.

Pricing writes and balance/terms adjustments: admin/boss within assigned
branches. Pricing read: admin/boss/sales. Ledger read: assigned staff; warehouse
receives stock only, no financial data. User management: admin only, including
target branch scope. The last enabled admin cannot be disabled/demoted.
The B2B role/customer branch cannot be converted through staff management.
Role/branch/password/account updates invalidate existing sessions. Staff edits
require the latest user revision; stale forms return 409 instead of overwriting.

Kiot preview and mapping contain retailer-wide records, so admin/boss need all
branch permissions. Global retail-price imports additionally require admin. Exports
and reconciliation are restricted to the assigned order branch. Customers are
never automatically merged by name or telephone. Product code AND unit must
match exactly; incorrect units are blocked rather than guessed.

## Pricing Rules

Priority is customer > group > default, at the customer's branch, on the
business date in Asia/Ho_Chi_Minh. A selected policy's explicit SKU price wins
over its discount. Discounts are integer percentages; prices are integer VND.
Inactive/expired policies and inactive customers do not receive a discount.
No policy means retail price, not an implicit 10 percent discount.
Overlapping active policies for the same branch/scope/target are rejected.
Updating requires the latest revision. Checkout always stores server prices.
Existing Sales order lines preserve snapshots; website edits requote all lines.
Approval-linked or nonpending orders cannot be edited. Customer/source stay
immutable. Website edits update checkout/contact/delivery data and recompute
the existing BAOTIN10 discount and shipping; the address becomes one complete
address string instead of retaining duplicated city/district fragments.

## Stock And Credit Cutover

Tables added: price_policies, inventory_balances, credit_balances,
ledger_entries, password_resets, integration_links, integration_runs,
integration_outbox. Together with the original 11 tables there are 19 tables.
User accounts gain disabled and revision; ledger entries have unique business references
and an opening-overdue adjustment for reversible payments.

Stock is `onHand - reservations`. Reservations count only Chờ soạn hàng,
Đang soạn and Sẵn sàng giao. Pending orders do not reserve. Confirmation
rechecks available stock inside the serialized DB transaction. Cancellation
before handoff releases reservations. Handoff into Đang giao reduces physical
stock once per order/SKU. Hoàn tất does not reduce it again. There is no
post-handoff return/restock/refund workflow yet.

Credit exposure is actual debt plus outstanding credit reservations. Posting
an issued credit order adds debt once. Creating a receipt does not affect
debt; reconciliation subtracts it, voiding adds it back once. B2C cash receipts
do not change B2B debt. An advance credit payment can create a negative balance
until handoff posts the debit. Unique references and a transaction protect
retries; stale UI commands return 409. Credit exception snapshots include other
reservations, and cannot permit a higher exposure than the approved snapshot.

Default payment terms are 30 days; admin/boss can set 0-365 days per customer.
At handoff, a credit order without an explicit due date receives handoff date
plus termsDays. Accountant can subsequently set a specific date through the
existing due-date command. Suspended B2B credit accounts cannot be handed off.
New posted overdue orders are computed from their unpaid amount and due date.
Opening overdue is a legacy aggregate, not a full aging ledger; payments are
bounded to current debt and reversal tracks any released opening overdue.
Do not treat this as a substitute for accounting reconciliation of old invoices.

Mock fallback physical stock applies ONLY to Quy Nhon. Other branches have
zero fallback stock until an actual balance is entered. Historical seed debt
is the opening snapshot; historical receipts/issues are NOT replayed. Initial
seed restarts do not overwrite existing balances or passwords. Do not remove
ledger references manually to replay a business operation.

Before selling: freeze pilot writes, reconcile open reservations/physical stock
and opening debts/overdue with KiotViet, enter reviewed balances with reasons,
check a sample complete transaction with accounting, then reopen the pilot.
No automated Kiot stock/debt/status writeback or scheduled sync is enabled.
Website ledger is a pilot control; KiotViet remains the operating source of truth.

## External Configuration

Configure secrets only in ignored backend env or secret manager:

```dotenv
FRONTEND_URL=https://your-frontend.example
SMTP_URL=smtps://user:password@smtp.example:465
EMAIL_FROM=accounts@your-domain.example
KIOTVIET_ENABLED=false
KIOTVIET_RETAILER=your-retailer
KIOTVIET_CLIENT_ID=your-client-id
KIOTVIET_CLIENT_SECRET=your-client-secret
KIOTVIET_BRANCH_MAP={"Quy Nhơn":123,"Tuy Hòa":456,"Nha Trang":789}
```

The branch IDs above are placeholders. Verify retailer branches before enabling.
Email production requires TLS. Recovery response bodies/status do not disclose
registered emails, including send failures. Failed tokens are removed and a
sanitized server warning is emitted; the UI acknowledges a request, not delivery.
Mail is sent synchronously, so timing hardening through a durable asynchronous
mail queue remains work before a public production rollout. Token hashes and
expiry are persisted, not plaintext tokens. The link
puts the token in the URL fragment to keep it out of server request logs.
Password updates revoke every session; users must log in again.

Kiot implementation follows the
[official Public API](https://www.kiotviet.vn/huong-dan-su-dung-kiotviet/retail-ket-noi-api/public-api/).
Fixed HTTPS endpoints: id.kiotviet.vn/connect/token and public.kiotapi.com.
Pagination is bounded to 10,000 records; partial/duplicate pages are rejected.
Preview snapshots expire after 30 minutes for mapping/price application.
Mapped price import preserves media/specification and does not create/publish
unknown SKUs. Inactive vendor SKUs are hidden. No remote image URLs are imported.
Confirm the shipping/tax model with the retailer before exporting live orders.

Export requires a confirmed, unissued order, current revision, all product
links, and a customer link for B2B. It creates an order with makeInvoice=false
and totalPayment=0, not an invoice or duplicate receipt. Outbox is written
before the network call. A lost response remains uncertain/sending; repeated
export is blocked. Reconcile searches the branch for the exact BAOTIN marker.
There is no automated resend or clearing of failed/uncertain outbox entries:
an operator must investigate vendor records first. Do not delete an outbox row
as a shortcut to retry. Already sent exports return their known external ID.

## Safe Deployment

1. Rotate database/JWT/seed secrets previously shared in chat; never commit env.
2. Back up DB and persistent media, test this release on a staging clone.
3. Inspect schema changes before allowing DB_SYNCHRONIZE=true. This release was
   synchronized ONLY to local schemas, not the user's Supabase. Synchronize can
   delete/change data; disable it after the reviewed schema update.
4. Deploy BE from repo root: npm ci, npm run build, dist/main.js. Keep certs/media
   runtime assets and persistent uploads; HTTPS, COOKIE_SECURE=true, correct
   FRONTEND_ORIGINS, NODE_ENV=production, SEED_MOCK_DATA=false.
5. Deploy FE: supported Node LTS >=22.13, npm ci, npm run build, npm run start.
   NEXT_PUBLIC_API_MODE=true and a full HTTPS BACKEND_URL. Do not cache API paths.
6. Run staging smoke tests with nonproduction users, then complete owner acceptance.
